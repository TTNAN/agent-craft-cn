## 这是什么

一句话：给中国开发者写技术文档的规范——说人话，去翻译腔，去 AI 味。

AI 写的中文文档有股味儿：中国开发者看三行就关掉。"值得一提的是""不仅提升了性能，更是优化了体验""首先、其次、最后"——这种话没有信息，只有姿势。

这个 skill 规定：先给结论再讲细节，段落要短，套话全删，代码示例必须能跑。写完自己读一遍，读着拗口的地方就是翻译腔，重写。

## 何时用

- 写 README、项目介绍
- 写代码注释
- 写 API 文档、教程、更新日志
- 写 PR 描述、技术方案文档
- 改别人文档里的 AI 味

## 工作流

### 第一步：先想清楚读者是谁

动笔之前，回答：这篇文档给谁看？

- 给新手看：别堆术语，每个术语第一次出现时给一句话解释。
- 给同行看：别讲废话，直接上干货，背景一句话带过。
- 给用户看（非技术）：别出现代码，多用截图和步骤。

读者不同，写法完全不同。没想清楚读者就动笔，写出来四不像。

### 第二步：结构——先给结论

固定顺序，不许反：

1. **先给结论**：一句话，这是什么、解决什么问题。
   - 好："一个让手机和电脑在同一 Wi-Fi 下互传文件的工具，不用数据线，不走云端。"
   - 烂："在当今数字化时代，随着远程协作需求的不断增长，本文将介绍一个创新的解决方案……"
2. **再讲怎么用**：最短可运行示例放最前面。读者 30 秒内要看到效果。
3. **最后讲细节**：配置项、原理、FAQ，往后放。

不许"背景介绍三段再进入正题"。读者是来解决问题的，不是来听你铺垫的。

### 第三步：段落要短

- 一段不超过 4 行。一段只讲一件事。
- 能用列表的，不用段落。步骤用编号列表，选项用无序列表。
- 代码块和表格是好朋友：配置项用表格，操作步骤用编号 + 代码块。

### 第四步：说人话检查清单

写完之后，逐条扫一遍，命中就改：

- [ ] 删掉"值得一提的是""需要注意的是""总而言之"——要说就直接说，别加引子。
- [ ] 删掉"不仅…更是…"——除非两边真有递进关系，否则就是空话。
- [ ] 删掉"不是…而是…"——除非真有对比，否则直接陈述。
- [ ] 删掉"首先、其次、最后"——用 1. 2. 3. 代替。
- [ ] 删掉"赋能""抓手""闭环""颗粒度""心智"——说具体动作。"赋能团队"改成"让团队能独立做 X"。
- [ ] 删掉"本文将介绍…"——直接介绍，别预告。
- [ ] 删掉"在…的背景下""随着…的发展"——删掉不影响信息，就删掉。
- [ ] 中英混排时，英文术语前后加空格："使用 Git 进行版本控制"，不是"使用Git进行版本控制"。
- [ ] 数字和单位之间加空格："10 GB"，不是"10GB"（中文语境下推荐）。

### 第五步：代码示例必须能跑

- 贴之前自己跑一遍。跑不通的示例，不如没有。
- 第一个示例控制在 10 行以内，让读者最快看到效果。
- 示例从简到繁：先给最小可用，再给完整版。
- 示例里的变量名、路径，用读者能直接替换的，别用 `foo`、`bar` 糊弄。

### 第六步：注释规范

- 注释解释"为什么"，而不是"是什么"。
  - 废话：`i++ // 计数器加一`
  - 好注释：`// 重试 3 次后放弃，避免雪崩拖垮下游`
- 删掉注释掉的旧代码。git 里有历史，不需要注释里考古。
- 公开 API 的注释写清楚：参数是什么、返回什么、抛什么异常、给个例子。

### 第七步：大声读一遍

写完，在心里大声读一遍。读着拗口、需要断两次才能断句的地方，就是翻译腔，重写。

测试标准：找个不做技术的朋友读第一段，他能说出"这是干嘛的"，就算过关。

## 示例

用户："帮我给这个项目写个 README。"

AI（错误示范）：

> # 我的项目
>
> 在当今快速发展的技术时代，效率提升成为了每个开发者的迫切需求。值得一提的是，本项目不仅是一个工具，更是一种全新的工作理念。首先，它能够显著提升你的工作效率；其次，它操作简单；最后，它完全免费。总而言之，这是一个值得一试的优秀项目。
>
> ## 快速开始
>
> 本文将介绍如何快速上手……

——全是姿势，没有信息。中国开发者看到"在当今快速发展的技术时代"就关掉了。

AI（正确示范）：

> # quickshare-local
>
> 让手机和电脑在同一 Wi-Fi 下互传文件，不用数据线，不走云端。
>
> ## 30 秒上手
>
> ```bash
> # 电脑上运行
> python share.py
> # 手机浏览器打开 http://192.168.1.5:8000
> ```
>
> 就这么简单。下面是详细说明。
>
> ## 功能
>
> - 上传：手机浏览器里选文件，点上传
> - 下载：页面上列出共享目录，点文件名下载
> - 只共享你指定的目录，别的看不到
>
> ## 安全
>
> 只在局域网内可用。出门记得关掉。

——第一句话就说清楚干嘛的，30 秒能跑起来，细节往后放。没有一句废话。

## 边界

- 不为了去 AI 味而把话说得油滑轻浮。说人话不等于说俏皮话，技术文档的第一要求是准确。
- 技术准确性优先于文风：术语不许为了"说人话"而自造词。该用"幂等"就用"幂等"，别写成"重复操作也没事的特性"。
- 不写超长文档：README 超过 200 行就该拆了，拆成 `docs/` 下的专题文档。
- 英文项目里的英文文档不归这个 skill 管。那是另一套规范。
- 翻译英文文档时，不许直译。先理解意思，再用中文重新讲一遍。直译是翻译腔的最大来源。
